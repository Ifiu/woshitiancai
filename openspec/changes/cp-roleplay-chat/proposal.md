## Why

用户想要一个手机端尺寸的文字小游戏来"嗑 CP"：在一个可自定义的世界观下，为自己设定的两个角色（以及后续加入的其他角色）生成由提示词驱动的互动对话，并可选择视角。目前这类需求只能靠通用聊天机器人拼凑，缺乏世界观/角色档案管理、视角切换和富表现力渲染能力。

## What Changes

- 新建一个移动端优先的单页 Web 应用（静态站点，无需后端）。
- 世界观管理：可创建多个世界观，每个世界观包含整体背景设定（时间、地点、规则、基调等自由文本），并可随时切换当前世界观；切换后对话上下文随之切换。
- 初始内容：首次启动预置一个占位世界观与两个初始角色"张极""左航"（档案与立绘均为占位内容，用户后续替换为自己的设定）。
- 角色管理：在每个世界观下创建角色档案（姓名、立绘、外貌、性格、背景、与其他角色的关系等自由文本字段），允许随时添加同一世界观下的其他角色；立绘初版为占位符（色块+名字），支持替换为图片 URL。
- 互动对话：用户输入提示词（剧情指令/某角色的台词），AI 根据当前世界观 + 出场角色档案 + 对话历史生成角色互动内容。
- 流式输出：AI 回复通过 SSE 流式接收并逐字渲染，可中途停止。
- 可选视角：每条/每轮生成时可选择叙事视角（角色 A 视角 / 角色 B 视角 / 上帝视角），不同视角影响生成内容的叙事口吻。
- 多角色加入：对话中可将世界观内其他角色拉入当前场景，参与互动。
- 富渲染：AI 回复中允许出现受约束的 HTML 片段（如手机消息界面、回忆卡片、系统提示框等剧情元素），前端白名单消毒后直接渲染；不引入 Markdown。
- 生成参数：温度等参数先固定为一组合适默认值，后续再开放调节。
- LLM 接入：使用 OpenAI 兼容的 Chat Completions API（stream 模式），用户在设置页自行填写 API Base、Key、模型名。
- 本地持久化：世界观、角色、对话记录、API 配置均存于浏览器 localStorage，支持导出/导入 JSON。

## Capabilities

### New Capabilities

- `worldbuilding`: 世界观的创建/编辑/切换、初始占位内容，以及世界观下角色档案（含立绘）的创建/编辑/删除与本地持久化。
- `roleplay-chat`: 基于世界观与角色档案的提示词驱动对话生成（SSE 流式）、可选叙事视角、多角色加入场景、AI 回复的受约束 HTML 富渲染，以及 LLM API 配置。

### Modified Capabilities

（无）

## Impact

- 全新代码：单页静态 Web 应用（HTML/CSS/JS，移动端优先布局），位于仓库根目录。
- 外部依赖：用户自备的 OpenAI 兼容 LLM API（运行时调用，需支持 stream 模式，无构建期依赖）。
- 数据存储：仅浏览器 localStorage，无服务端；隐私数据（API Key、对话）不出用户设备，仅发往用户配置的 API 端点。
- 假设（已确认）：无后端、无账号体系；中文 UI；SSE 流式输出；生成参数先固定默认值；不做 Markdown，改用受约束 HTML 渲染；初始角色"张极""左航"与初始世界观先用占位符。
