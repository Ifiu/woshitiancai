## Why

应用目前按手机端尺寸硬编码：`#app` 与底部弹层最大宽度均为 480px，桌面浏览器中只剩居中的窄长条，宽屏空间完全浪费；同时缺少键鼠交互支持（无 hover 反馈、无 Enter 发送、滚动条为系统默认样式）。用户希望在完全保留手机端体验的前提下，让桌面网页端同样好用。

## What Changes

- 新增宽屏响应式断点：视口 ≥768px 时适度放宽主容器（平板档约 640px，桌面档 ≥1024px 约 860px，始终居中）；≤767px 手机端布局与交互保持现状、完全不变。
- 宽屏下底部弹层（世界观 / 角色 / 设置 sheet）从「底部抽屉」变为「居中对话框」：恢复四边圆角与底边框，限制最大宽度与最大高度。
- 宽屏下舞台区与立绘位按比例放大（舞台更高、立绘更大），对话气泡增加桌面端阅读宽度上限，避免超宽行长。
- 修正宽屏下的尺寸遗漏：`#toast` 等以 `vw` 定宽的元素在桌面端增加固定像素上限。
- 键鼠交互优化（仅在支持 hover / 精确指针的设备生效，触屏不受影响）：
  - 按钮、场景条 chip、消息操作、列表条目等可点元素增加 hover 视觉反馈；
  - 聊天区、场景条、舞台区、弹层统一替换为贴合主题的细滚动条样式；
  - 输入框支持 Enter 发送、Shift+Enter 换行（含中文输入法组词期间 Enter 不误触发的保护），手机端行为不变。

## Capabilities

### New Capabilities

- `desktop-adaptation`: 桌面/宽屏浏览器下的响应式布局适配（断点、容器宽度、弹层形态、舞台与阅读尺寸）与键鼠交互优化（hover 反馈、主题滚动条、Enter 发送）。

### Modified Capabilities

（无——`openspec/specs/` 当前为空，无主 specs 可修改。）

## Impact

- 受影响代码：仅 `index.html` 单文件——`<style>` 内新增媒体查询与 hover/滚动条规则、少量既有选择器增补；`bindEvents()` 中新增输入框 `keydown` 处理。无新依赖、无构建流程变化。
- 不受影响：localStorage 数据结构、LLM API 调用与流式逻辑、富渲染白名单、世界观/角色业务逻辑、`preset/` 与 `portraits/` 内容。
- 兼容性：手机端（≤767px）渲染结果与交互保持不变；`env(safe-area-inset-*)`、`100dvh` 等移动端机制原样保留；媒体查询与 `hover`/`pointer` 特性查询均为渐进增强，旧浏览器自动回退到现状。
- 明确不做：宽屏多栏布局、页面铺满无最大宽度、viewport meta 调整、PWA/打包分发、移动端任何交互改动。
